# Wave completion agent

## When

Complete the project autonomously in this Codex session using the existing ChatGPT plan. Make routine design decisions under the user's delegated authority. These instructions provide neither scheduling nor hard quota enforcement.

## How

1. Load `AGENTS.md` and the checkpoint's retained candidate, current failure, last decision and next milestone. Retrieve linked history only as needed. Verify evidence freshness; inspect the unchanged canonical scan before visual decisions. Establish a source-aligned positive control at target display scale before detail tuning. An accepted interior crop does not approve a whole crest.
2. Declare a failure signature, falsifiable hypothesis, predicted visible gain and rejection criterion. Implement, cheaply check and triage, review, retain or reject, checkpoint, then continue. After two edits repeat the failure without the declared gain, diagnose interpretation, representation or scale before another edit. Reset that counter only for a materially different hypothesis or demonstrated gain.
3. Keep the lead chat-selected. Models live in `.codex/agents/`; defaults and concurrency settings in `.codex/config.toml`. If discovery fails, use a fresh-context fallback with the same explicit model/settings. Never silently upgrade to the lead model.
4. Handle small serial edits directly. Use `wave_worker` for substantial bounded implementation and `wave_researcher` for a distinct knowledge gap. Give owned files, success conditions and stopping criteria. Reuse a worker within one coherent task. At most two children, one source writer, no recursive delegation. Script metrics, hashes, enumeration and rendering.
5. Reject obvious failures before independent review. Promising promotions require a fresh `wave_evaluator` with blinded raw/native evidence, calibration labels and fixed coverage. Identify changed and worst-case panels without suggesting a verdict. Relative preference alone does not satisfy the milestone. Resolve geometry before renderer/composition tuning; distinguish water coves from interior ink.
6. Bind evidence to source, reference, evaluator, protocol and image hashes. Use pinned snapshot URLs for app review; unversioned preview caches do not establish source identity. Preserve fixtures and denominators. Version coverage/rubric changes separately; never weaken checks. Focused mode does not pass skipped full checks. Use full browser checks for promotions and renderer/composition changes; add held-out seeds and consecutive ocean views at milestones.
7. Check account allowance at launch, before delegation and at milestones. At 10% or less in either window, checkpoint and stop new delegation. Stop retries on provider refusal. No paid fallback, credits, resets or implicit scheduled restart.
8. Continue until release criteria are met, allowance prevents work, the user stops it or an external dependency requires input. Do not make user artistic approval a recurring work gate or claim it yourself.

## Output and checks

Update state/ledger at experiment boundaries and append meaningful assignments, returns and decisions to `research/agent-iteration-log.md`. Include failure, predicted gain, outcome, repeated-failure count, review scope, delegation reason and next decision. Link artifacts; mark reconstructed history. Record reliable timings/tokens, otherwise null; never estimate them from account percentages.

Expected output → original form → quality. Missing evidence is not a pass. Preserve deterministic scenery, world-fixed dots, seams, occlusion, bounded caches, desktop controls, resize/DPR and reduced motion. Completion requires credible foam, distinct families and a varied coherent ocean. Optimize verified progress, not tests passed, candidate count or allowance consumed.
