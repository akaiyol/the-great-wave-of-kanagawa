# Proposed project contract

The user defines two equally important goals. A visually impressive image cannot substitute for a capable, efficient agent system, and workflow sophistication cannot substitute for convincing generated artwork.

**ART — procedural Great Wave ocean.** Final output: a standalone desktop browser experience, visually evocative of the canonical Hokusai scan, generated through LingDong-style composition, object geometry, contours and details. Slow continuous horizontal exploration, pause/manual travel, reduced motion, clouds, deterministic revisits and bounded working memory. Finished-wave sprites and a rescaled standard silhouette fail.

Acceptance floors:
- A1: unlabeled whole-view comparison at1280x720 and1920x1080 supports immediate Great Wave recognition, with canonical silhouette, connected unequal foam, negative space, contours and palette. Independent informed review and final user artistic acceptance are separate evidence.
- A2: profiles, crest topology, foam and water contours are generated geometry; at least3 materially different construction families, evaluated across16fixed seeds including held-out cases. No fading, floating roots or hidden failed forms.
- A3: composition includes wave groups, depth, quiet water and clouds;32consecutive generated regions have no exact duplicate new geometry and pass a visual repetition/seam review. Deterministic return after eviction is verified. No untested infinite-uniqueness claim.
- A4: controls, pause, reduced motion, hidden-tab handling, resizing and DPR1/2 pass desktop checks;30-minute travel has no runtime errors or unbounded cache growth. Record hardware and frame timing; p95<=33.3ms at1920x1080,DPR1 on the documented test machine.

**SYSTEM — efficient evaluated agentic development.** Final output: a small reproducible workflow with independent strategy challenge, technical/visual evaluation, bounded evidence-linked lessons, and reliable continuation within actual runtime limits. Learning means improved decisions and workflow verified by evidence, not a claim that model weights train themselves.

Acceptance floors:
- S1: every new phase links a goal, predicts an observable outcome, sets a test/stopping budget, obtains independent strategy challenge, records its result and completes final5%process review. No self-granted artistic acceptance.
- S2: a critic demonstrably preserves supported gains, identifies failed constructions and distinguishes missing evidence from a disproven premise. Assess outcome-hidden historical packets and at least6prospective decisions, including critic mistakes; a JSON gate is not proof of judgment.
- S3: compare at least6matched experiments against a declared baseline. Equal-or-better independently reviewed quality must accompany lower median active time and estimated tokens per retained improvement; report unknown actual compute and tradeoffs honestly. Laptop-sleep gaps are reported separately.
- S4: investigate precise blockers using primary research/original implementations; record the mechanism transferred, evidence, limits and a retry condition. Keep bounded lesson memory and discard failed active implementations. No speculative research or growing agent fleet without demonstrated benefit.
- S5: startup and continuation retain both goals, user resource ceiling and current evidence. Missing/stale activity is detected; active-goal state is checked separately. Every architecture change updates its manifest and README diagram in the same change. Technical checks fail on drift. Do not promise execution while the local host is asleep.

Implementation proposal: one canonical JSON goal definition and pinned acceptance floors; generated GOALS.md plus short README goal summary; one architecture manifest generating the README Mermaid block; source pins for role/workflow inputs; project-contract sync/check commands; the phase gate checks valid goal IDs and a statement protecting the other goal; the generated brief always shows both goals and unmet criteria. Existing docs, role models and one-child/one-writer constraints remain. No dashboards, paid services, scheduler or automatic relaxation of acceptance criteria.

The lead owns coherent definitions, implementation, documentation, validation and GitHub publication. Agents may recommend changes, but cannot silently weaken goals or accept their own artwork. System effectiveness remains unproven until prospective and baseline evidence exists.
